# Deploying Lumora

Recommended setup: **Render** (PostgreSQL with pgvector + the Dockerised FastAPI API) and **Vercel** (React frontend).

## 1. Backend + database on Render

1. Push the repository to GitHub.
2. In Render, choose **New → Blueprint** and select the repo. `render.yaml` creates:
   * `lumora-db`, a PostgreSQL database. Render's Postgres supports the `vector` extension, and the first migration runs `CREATE EXTENSION IF NOT EXISTS vector`.
   * `lumora-api`, a Docker web service built from `backend/Dockerfile`, with health check path `/api/health`.
3. Environment variables (Render dashboard → `lumora-api` → Environment):

| Variable | Value |
|---|---|
| `DATABASE_URL` | Filled from the database automatically (`postgres://…` is normalized to `postgresql+psycopg://…`) |
| `JWT_SECRET` | Auto-generated by the blueprint. The app refuses to start in production with the default value |
| `ENVIRONMENT` | `production` (enables HSTS and the JWT secret check) |
| `CORS_ORIGINS` | Your Vercel URL, e.g. `https://lumora.vercel.app` |
| `AI_PROVIDER` | `demo` (free), `openai` or `anthropic` |
| `AI_API_KEY` / `AI_MODEL` | Only for real providers. Mark the key as secret |
| `EMBEDDING_PROVIDER` | `local` (default) or `openai` (+ `EMBEDDING_API_KEY`) |
| `SEED_DEMO_USER` | `true` creates `demo@lumora.app` with simulated history for portfolio visitors |

On boot, the container runs `scripts/start.sh`: `alembic upgrade head` → optional demo seed → `uvicorn` on `$PORT`. The curriculum
and RAG library are seeded idempotently at startup. The ML models are baked into the image at build time (synthetic bootstrap).

> Free Render instances sleep when idle, so the first request can take around 30–60 s.

## 2. Frontend on Vercel

1. **Add New → Project**, import the repo, set the **Root Directory** to `frontend`.
2. Framework preset: Vite (already declared in `frontend/vercel.json`, along with the SPA rewrites).
3. Environment variable: `VITE_API_URL=https://<your-render-service>.onrender.com`.
4. Deploy. Then add the Vercel URL to `CORS_ORIGINS` on Render.

## 3. Single host with Docker Compose

```bash
cp .env.example .env            # set a strong JWT_SECRET
docker compose up --build -d
# App: http://localhost:8080   API docs: http://localhost:8080/docs   API direct: http://localhost:8000
```

nginx serves the built SPA and proxies `/api`, `/docs` and `/openapi.json` to the backend, so only one origin is exposed.

## 4. Switching on a real LLM

```bash
AI_PROVIDER=anthropic   AI_API_KEY=...   # default model: claude-opus-5-5 (override with AI_MODEL)
AI_PROVIDER=openai      AI_API_KEY=...   # default model: gpt-4.1-mini
```

Both providers return **schema-validated structured output**. If a call fails, times out, is refused or returns invalid
JSON, Lumora falls back to the grounded demo provider and says so in the UI. The public landing-page tutor demo
always uses the demo provider, so anonymous traffic can never spend API credits.

## 5. Production checklist

- [ ] `ENVIRONMENT=production` and a unique `JWT_SECRET`
- [ ] `CORS_ORIGINS` contains only your frontend origin(s)
- [ ] HTTPS everywhere (Render and Vercel provide it)
- [ ] Rate limiting: the built-in limiter is per instance. For more than one instance, back it with Redis
- [ ] Database backups enabled
- [ ] Retrain the models on real data once there is enough of it: `python -m app.ml.train --source db`
